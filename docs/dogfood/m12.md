# Dogfood m12

## Gate: MAMA browser host missing (M7 not started)

The gate for M7 requires MAMA's per-group meshing and its browser host to be merged. Per-group meshing is present. The browser host, as this task defines it (a viewport: mount on a canvas, load a document, set the camera, render one frame, plus the build directory and its command), is not.

What is present in `../MAMA` (read only, HEAD 864ebc3, clean tree):

- Per-group meshing: `meshAssets(doc, { pool, groups, output, onProgress, onNotice })` in `src/core/game/mesh-assets.ts`, reached as `mama/core/game/mesh-assets.js`. It returns one result per group: `{ group, asset, output, parts: [{ partId, name, frame, subMeshes: [{ material, positions, normals, uvs?, indices }] }], materials, error }`. A refusal is a value (`error: { code: 'MESHER_GROUP_UNSUPPORTED', message, fix }`), not a throw, and the message names the group. `AssetMeshPart` carries no rigid flag.
- Material compiler: `compileMaterialGraph(def, key)` in `src/core/material-graph/compile.ts`, reached as `mama` (exported from `src/sdfm.ts`) and `buildMaterial(doc, id)`. It returns a `CompiledGraph` with `wgslBody` (statements of `mat_graph_K`, ending in `return MaterialFull(...)`), `helpers`, `constants`, `authored`, `bump`, `displace`, and related fields. Two things the adapter needs are absent: no single `MaterialFull` WGSL source string (the full text is assembled in `src/core/material-graph/slots.ts`) and no explicit blend or translucency mode and no stable hash or key.
- Browser build: `setupBrowserHost({ workerUrl, manifoldWasmUrl, size?, workerMode? })` in `src/browser/index.ts`, reached as `mama/browser`. It returns a compute worker pool running `dist/browser/compute-worker.js`, built by `npm run build` (tsc). This is a worker pool that meshes, not a viewport.

What is missing for the browser host:

- No canvas mount. Nothing in `src/` or `examples/` creates a WebGPU context or renders to a canvas. `examples/mesh-assets` draws a CPU rasteriser to 2D canvases.
- No document load into a viewport, no camera API, and no render-one-frame call.
- The SDF Modeler viewport the task refers to lives outside this checkout (no sibling SDF_Modeler_MCP here), so it cannot be surveyed.

Impact: the README `## MAMA calls` table would have no entries for mount, load, camera or render, and the acceptance "the README call table names functions that exist in ../MAMA" cannot be met for them. The package manifest and the adapter cannot be written against a browser host that does not exist, so `packages/raa-sdfm/` was not created.

Needed from the lead to report to the supervisor: a MAMA change that exposes a browser viewport host (mount on a canvas, load a document, set the camera, render one frame, and the build directory and command), and a single composed `MaterialFull` source plus a blend mode and a stable key on the compiled graph.
