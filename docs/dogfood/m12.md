# Dogfood m12

Friction met while writing the M7 package manifest and the MAMA call table.

- missing_context: the brief asks for a browser host that mounts a viewport, loads a document, sets the camera and renders a frame. MAMA's only browser export is `setupBrowserHost`, which returns a meshing worker pool. Evidence: `../MAMA/src/browser/index.ts:111`. The README records the gap; the product owner holds the decision.
- unclear_instruction: the answer on the material input says `MaterialFull` is read from `src/core/material-graph/slots.ts`. The struct is declared in `src/core/material-graph/wgsl-parts.ts:242`, and `slots.ts` only constructs it. Evidence: `../MAMA/src/core/material-graph/wgsl-parts.ts:242`.
- unclear_instruction: the answer on the call table says it lists "nothing else", but the bridge also needs `readSdfm` (to build the `doc` argument of `meshAssets`) and `HELPERS` (to resolve helper ids to WGSL). Both are listed in the README table, and this choice is flagged for the lead.
- environment: `node --test packages/raa-sdfm/test/` (a directory argument) fails on the sandbox Node 24.21 with MODULE_NOT_FOUND and exits 0 while reporting "test failed". The proof and `.nmc/commands.json` use the quoted glob `packages/raa-sdfm/test/*.test.js` instead, which passes 79 of 79. Evidence: `proofs/m12-sdfm.mjs` unit check.
- missing_context: a compare scene has no helper to derive `settings.camera` from a fixture's bounds. The framing rule lives only in the comments of `examples/sdfm-compare/lib/runner.js`, so the camera numbers in `examples/sdfm-compare/scenes/m12-fixtures.js` were computed by hand from each fixture's `bounds` (bounding sphere, 1.1 margin, fovY 45, pane aspect 640x720). A small `tools/` helper, or a documented formula in the S14 contract, would avoid repeating this.
