## Frictions

1. **The hardware compatibility adapter cannot run the forward pipeline.**
   Exact first validation error (the client log's redaction obscures part of
   `location`, reconstructed from the diagnostic):

   ```
   The interpolation sampling (First) of the vertex output at location 2 is not supported in compatibility mode
    - While calling [Device "raa-device"].CreateRenderPipeline([RenderPipelineDescriptor ""raa.forward.pipeline""]).
   ```

   Subsequent diagnostics say `[Invalid RenderPipeline "raa.forward.pipeline"] is
   invalid due to a previous error`, followed by invalid command-buffer submission.
   Done by hand: inspected the initial PNG, then installed a compatibility-device
   `uncapturederror` listener in `demos/m2-scene/web/main.js` and made the run op
   reject with the first error. A second GPU-client capture confirmed the failure.
   nomorechat must expose a core-level hardware WebGPU adapter that supports this
   pipeline, or the lead must authorize and arrange a compatibility shader path
   (including checking material-storage support). Any raa-core change requires
   lead authorization. Then rebuild with alloc-count and recapture; the current
   timings are not a valid rendering-performance baseline.
2. **GPU-client diagnostics hide asynchronous rendering failures.** The first job
   returned success, `nonEmpty: true`, and a black PNG; no validation messages were
   returned. Done by hand: added the page listener described above. nomorechat must
   return page console and WebGPU validation diagnostics with the job so a successful
   transport/op return cannot silently stand in for successful rendering. The lead
   should also investigate the false-positive readback in the consumed
   `raa-web`/`raa-core` non-empty probe; those modules were left untouched.
3. **Capture logging redacts ordinary text and the help is too sparse.**
   `gpu-capture.mjs` redacts every environment value, corrupting numbers and even
   `location` in errors. Client `--help` only prints the render usage, with no way
   to retrieve console diagnostics. Done by hand: read the result JSON for exact
   measurements and inspected the client's diagnostic handling to confirm that
   normal successful runs do not return console logs. nomorechat must identify
   secret values explicitly for redaction and document how to retrieve page logs.
