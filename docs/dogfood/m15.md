# M15 dogfood: animation hooks from JS

A short walk-through of the m15 API as a JS user. Reference: `docs/api/m15-animation.md`.
The scene it follows is `examples/lookdev/scenes/m15-waddle.js`.

## Rigid hierarchy

Build the parts as nodes once, then move the whole tree with one `setTransforms` per frame.
Children inherit the parent transform, so the feet and head follow the body.

```js
const body = engine.addNode(null);
const head = engine.addNode(body, [0, 1.6, 0]);
const foot = engine.addNode(body, [0.2, 0, 0]);
const bodyInst = engine.addMeshInstance(body, bodyMesh);
const headInst = engine.addMeshInstance(head, headMesh);
const footInst = engine.addMeshInstance(foot, footMesh);

engine.setTransforms(new Uint32Array([body, head, foot]), pose); // every frame
```

The penguin rig keeps the body origin at the ground contact point, so a squash about the
origin keeps the feet planted.

## Squash on a foot plant

`setSquash` squashes an instance along a local axis and keeps its volume. Use it on the foot
when it lands, and reset it when the foot lifts.

```js
engine.setSquash(footInst, { amount: 0.25 }); // squash along +Y on plant
engine.setSquash(footInst, { amount: 0 });    // rest
```

## Jiggle from node motion in an interactive loop

`setJiggle` attaches a spring driven by the world motion of the node. It needs a real time step,
so use it in an interactive loop, not in a fixed-time capture.

```js
engine.setJiggle(bodyInst, { height: 1.2 });
function frame(nowMs) {
  engine.setTransforms(nodes, pose);
  engine.render(nowMs); // steps the springs
  requestAnimationFrame(frame);
}
```

Call `setJiggle(instance, null)` to remove the spring.

## Direct jiggle for fixed-time captures

A capture renders at a fixed time, so a spring never moves there. The scene writes the jiggle
record itself with `setInstanceExtras`, which takes one batch for many instances: tint (floats
0..3), squash (4..7), jiggle (8..11) and 16 params (12..27) per instance, 32 floats in all.

```js
const ids = new Uint32Array([bodyInst, headInst]);
const data = new Float32Array(32 * ids.length);
data.set([1, 1, 1, 1, 0, 1, 0, 0, 0, 0, 0, 1.2], 0);  // body: jiggle height 1.2
data.set([1, 1, 1, 1, 0, 1, 0, 0, 0, 0, 0, 1.2], 32); // head
engine.setInstanceExtras(ids, data);
```

## Tints

`setInstanceTint` multiplies the base colour (sRGB `rgb`) and the opacity (`a`). The `tints`
variant tints three copies of the penguin and leaves the blue hero untinted.

```js
engine.setInstanceTint(bodyInst, [1.2, 0.9, 0.8, 1]); // warmer
engine.setInstanceTint(bodyInst, [1, 1, 1, 0.5]);     // half opacity
```

## Waddle variants

The scene `m15-waddle` drives a 1.2 s waddle cycle. Its variants are:

- `f00` to `f11`: frames at timeMs 0, 100, ..., 1100. `f00` and `f06` are judged against
  `/refs/ref-1.png` and `/refs/ref-2.png`.
- `deform-on` and `deform-off`: the same frame with and without the vertex deform.
- `tints`: all four penguins in view, three of them tinted.

Captures are written to `proofs/captures/lookdev/m15-waddle--*.png`, for example
`proofs/captures/lookdev/m15-waddle--f00.png` and `proofs/captures/lookdev/m15-waddle--tints.png`.
Records are in `proofs/results/lookdev/m15-waddle--*.json`.

## Commands

`.nmc/commands.json` runs the chain: `build-lookdev`, then `cargo-check`, then `capture-m15` (the 13 remaining
variants, one worker), then `proof-m15`, then `p2-smoke`. Each step runs after the one before it.
The owner explicitly accepted the existing `f00` and `f06` looks below the judge minimum
(task 5287). Their PNGs and original judge records are preserved, including scores and exits;
the proof recognizes only those accepted image hashes and still requires valid judge verdicts.
All 15 variants must have non-empty hardware records and matching capture PNG hashes.
The proof also runs the `raa-deform` unit tests, wasm check and m15 API documentation check.
