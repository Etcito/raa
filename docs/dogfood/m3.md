## sdfm alias: git objects only; the prescribed esbuild fallback cannot run here

- **What broke:** the read-only alias `sdfm` resolves to `/root/nmc/sdfm`, but that
  directory contains only `.git`: `git status` there lists every tracked file as
  deleted, and there is no `node_modules`. Reading is still possible through the
  object store (`git -C /root/nmc/sdfm show 50b45d58...:src/core/hybrid/leaf-mesh.ts`,
  and `git archive HEAD | tar -x -C /tmp/opencode/sdfm` outside both repositories),
  so this documentation card was not blocked.
- **What broke for the tool:** `node --experimental-strip-types` cannot import
  `src/core/hybrid/leaf-mesh.ts` directly: the source writes `.js` specifiers for
  `.ts` siblings, and node's type stripping does not rewrite `.js` → `.ts`
  (`ERR_MODULE_NOT_FOUND .../src/core/sdf/profile.js`). With a built-in
  `module.registerHooks` resolver that retries `.js` as `.ts` it then fails on
  `polygon-clipping` (imported by `svgplus/shape-region.ts`, reachable from
  `registry.ts`) because the alias has no `node_modules`. The fallback the
  `sdf-ref-tool` module spec prescribes (bundle with the esbuild found in the
  checkout's `node_modules`) is therefore unavailable in this sandbox as well.
- **What was done by hand (evaluation only, never written to `sdfm`):** `/tmp/opencode/sdfm`
  was extracted from the object store; a `.js`→`.ts` resolver plus a no-op
  `polygon-clipping` stub in `/tmp/opencode` loaded the module; the measurements in
  `tools/sdf-ref/README.md` §3 (counts, minima, welding, closure, signed volume,
  the capsule mismatch) come from that loaded module. To exercise the mapping's
  `call` path, a second scratch copy re-exported the five private generators
  (`export { ellipsoid, roundBox, capsule, frustum, torus }`) and was called with
  explicit counts; the unmodified module stayed byte-identical in all comparisons.
- **What nomorechat or the lead must do:** materialise the `sdfm` alias as a real
  read-only checkout with its files and `node_modules` so `gen-leaf-fixtures.mjs`
  can run the prescribed esbuild fallback, or bless the in-sandbox fallback above
  (resolver hook + stub) as the tool's temporary entry. The git-object-only alias
  blocks the fixture tool card, not this documentation card.

## mapping v1: two findings resolved by the Q3 directive, one new one recorded

- Resolved by the Q3 amendment: (1) vec3 SDF params (`size`, `radii`) are written as
  per-component keys `<param>.x|.y|.z`; (2) all counts are `{count, ref, min,
  multiple, source}` rules with `count(s) = max(min, multiple * round(ref*s /
  (24*multiple)))`, so the 48 fixture cases are distinct and LOD0 reproduces the
  reference defaults exactly. Applied verbatim in `tools/sdf-ref/README.md` §4.
- **New finding (recorded in §5, not worked around):** `capsule.height` is affine
  (`2 × halfHeight + 2 × radius`), because S3's `halfHeight` is the segment half
  (`raa_prims::PrimParams::bounds` = `[radius, halfHeight + radius, radius]`) while
  SDF Modeler's `height` is the total including caps (`basic.ts:240`,
  `leaf-mesh.ts:179`). Mapping v1's `sdf_value = scale × S3 value` has no offset
  term, so no valid `capsule.height` entry exists; the mapping in §4 leaves it out,
  the coverage rule makes the mapping invalid, and the fixture tool must refuse it
  until the lead amends mapping v1 (minimal fix proposed in §5: one optional
  additive term per param entry).
- The sandbox has no `$NMC_GPU_CLIENT`/browser work in this card: the deliverable is
  documentation only. No capture, no Vite build, no GPU use.
