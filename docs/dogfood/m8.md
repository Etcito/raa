# M8 dogfood: GPU client, sandbox and tooling

## m08-sky-ibl capture handoff (card 4505), 2026-10-23

What was done by hand:
- **Reference prefix.** The judge needs `--ref-prefix <p>` (references are `<p>ref-N.png`).
  The producer task said "the prefix the lead supplies", but no prefix was given in the task
  prompt. `.nmc/commands.json` at the base of this card (written by the api-m8 types card,
  commit 5fa6eef) already used `--ref-prefix /refs/`, and the sandbox prompt names `/refs`
  as the read-only operator reference mount (`/refs/ref-1.png` .. `ref-4.png`). That value
  was kept: it is the generic sandbox mount, not a host path, host name or token. If the
  programmatic card has no `/refs` mount, `lookdev-capture.mjs` stops before capturing with
  "reference image(s) missing" and the lead supplies the prefix (a URL or another mount).
- The commands file cannot use an environment variable for the prefix (only
  `$NMC_JUDGE_CLIENT` and `$NMC_GPU_CLIENT` are expanded), so the prefix is written literally.
- Camera, sun and preset look were chosen without a render: a model card cannot run a GPU job.
  The first capture (card 4506) is the first time anyone sees the framing; tuning follows it.

What nomorechat should do instead:
- Expose the operator references to commands as an expanded variable (e.g. `$NMC_REFS_PREFIX`,
  like `$NMC_JUDGE_CLIENT`), so no scene or commands file has to know where they are mounted.
- Put the reference prefix in the producer task prompt when the task depends on it, instead
  of leaving it to a value an earlier card happened to write.
- Let a model card run one small preview render (one variant, low resolution) to check the
  framing before the programmatic card spends a full capture and judge run on it.
