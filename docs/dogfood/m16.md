# M16 animation brick capture

Canonical `det-selftest` inputs, in order: `(seed=0,ticks=0)`, `(1,60)`,
`(305419896,600)`. No expected hash is embedded in the capture runner.

The programmatic card runs `node scripts/anim-capture.mjs --case det-selftest`.
It probes the GPU client with a blank page, builds the local bricks, stages
`dist/anim-brick` with its manifest, shared helpers and animation package, then
publishes it and uses the returned `page_ref` for three separate `render` calls.
The zero-tick case is the smallest diagnostic before the two simulation cases.
Calls are sequential (one child process at a time, also within default NMC_CPUS=1).
`NMC_GPU_WAIT_S` defaults to 60 seconds; each client call is bounded by the smaller
of that value and the 60-second step ceiling. Invalid waits fail; unavailable
clients, timeouts and invalid results fail without retrying or substituting hashes.

The atomic output is `proofs/results/anim/det-selftest.json`: capture name,
milestone, timestamp, genuine adapter and hardware classification, brick metadata,
published wasm raw/gzip sizes and SHA-256, canonical `results`, and unmodified
browser `runs` including each requested case/seeds/ticks. The diagnostic page has
no screenshot operation; no PNG, timing or visual evidence is fabricated.
Software/fallback adapters are refused. The staged wasm digest must match the build
manifest and remain unchanged throughout capture. Raw client diagnostics and
page references are omitted from logs to avoid leaking credentials.

Status: runner prepared; Chrome capture and full parity verification have not run
on this model card. The existing queue entries remain intact. Capture waits for
those entries, `verify-m16-anim` waits for successful capture, and the final
`cargo check` waits for the milestone proof. `proofs/m16-anim-brick.mjs` must be
supplied by the milestone proof task before programmatic execution; it was absent
when this runner was prepared. That proof must validate native/Node/Chrome parity
and the clean rebuild. A failed capture leaves any earlier committed record intact,
but its nonzero exit prevents dependent verification from accepting that old record.

Runtime capture failures append timestamped, secret-free friction below.
