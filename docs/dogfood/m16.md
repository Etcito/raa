# M16 animation brick

The M1 S1-0 brick path builds `raa-anim` locally and runs it in Node and in Chrome. Per
the owner rule (no hash proofs, ever) the milestone no longer keeps hash or SHA
evidence: the proof only checks that both environments load the brick and return
well-formed `det-selftest` records for the canonical inputs.

## Fixtures

`case` is `det-selftest`; the ordered pairs are `(seed=0, ticks=0)`,
`(seed=1, ticks=60)` and `(seed=305419896, ticks=600)`. Each result has exactly
`{case, seed, ticks, hash}` with u32 JSON seed/ticks and the brick's eight-digit
lowercase hexadecimal Fnv1a32 output. The zero-tick case exercises the simulation's
zero-step behaviour; the other two exercise simulation updates. The hash is output data
only: the proof validates its shape, never its value against native, Node or Chrome.

## Functional verification

`node proofs/m16-anim-brick.mjs` prints five CHECK lines:

- `unit`: `cargo test -p raa-det -p raa-anim-js`.
- `bricks`: `dist/bricks` removed, `scripts/build-bricks.sh` stages `raa`, `raa-sdfm`
  and `raa-anim` with `bricks.json`; the animation wasm gzip must be <= 300000 B and
  the measured raw/gzip sizes are printed.
- `det-guard`: `scripts/check-det.sh` reports 0 hits.
- `node-load`: `loadRaaAnim()` loads the staged brick in Node (default, package
  directory, paths, URL and preloaded byte forms) and `selftest` returns the three
  canonical records.
- `browser-load`: `scripts/anim-capture.mjs` stages `examples/anim-brick`, serves it on
  127.0.0.1, loads it in Chrome and calls `run()` separately for each canonical
  seed/ticks; the page returns the three records and names its adapter.

No hash or SHA value is compared by any check. The previous committed record
`proofs/results/anim/det-selftest.json` and the queue entries that captured or compared
hashes were deleted. `bricks.json` still records `sha256` as package data and each
result still contains the brick's hash output; neither is used as a gate.

functional load-and-run check, not a GPU render capture; no adapter requirement or
screenshot is part of the M1 brick proof. The programmatic card reruns the proof and
the workspace checks in a clean worktree.
